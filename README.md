# 燃 · 减脂打卡

移动端优先的单文件 PWA。零外部依赖、可离线、数据只存本机（并自动备份到本仓库）。

## 直接用

**https://lpyyyyyyyyyy.github.io/fit-tracker/**

> ⚠️ 注意：`github.com/lpyyyyyyyyyy/fit-tracker` 是**代码仓库**，打开只会看到文件列表。
> 上面那个 `github.io` 的地址才是**能用的 App**。两个地址长得很像，别看错。

手机上建议：**Safari** 打开 → 分享 → **添加到主屏幕**。
加完就是个独立 App，全屏、有图标、能收通知。

## 功能

**今日**
- 时间轴：一天所有要做的事按时间排好，点一下就打卡
- 每个时段的**水分点阵**（咖啡、牛奶都算进总液体量）
- 点餐食条目 → 展开**怎么做**（火候、时间、调料、份量换算）
- 16+8 轻断食窗口（默认 08:30–16:30，可改）
- 步数：手填

**体重**
- 输入即画图（不用等失焦）
- 7 日均线 + 目标线
- 显示「比上次重/轻多少」

**进度**
- 主目标进度条 + 第几天 / 速度 / 预计达标
- **肌肉守护分**：6 个因子加权（训练 35% / 蛋白 22% / 缺口 18% / 睡眠 13% / 活动 7% / 速率 5%）
- **忍不住嘴**：记下多吃了什么，换算成「少掉多少斤」，并且**计入实际摄入**（模拟页的预测会跟着变）
- 打卡日历

**模拟**
- 30 天体重与 BMI 预测（虚线 = 预测）
- **基础代谢计算器**：BMR / TDEE 拆解，活动系数可调
- 「今天如果不做，后果是什么」（按危害排序）
- 过去两周：实际水平 vs 满分计划

**训练**
- 12 分钟 4 个动作，计时器自动衔接
- **跳过这节**：不用等热身和组间休息
- 弹窗形式，支持下拉关闭

**设置**
- 目标锁定：设定后不可改，达成才解锁
- 16+8 开关与窗口
- 自动备份到 GitHub
- 强制更新（缓存出问题时点这个）

## 算法来源

| 模型 | 公式 / 依据 |
|---|---|
| 基础代谢 | Mifflin-St Jeor：`10×kg + 6.25×cm − 5×age + 5`（女 −161） |
| 体脂率估算 | Deurenberg：`1.20×BMI + 0.23×age − 10.8×sex − 5.4` |
| 围度法体脂 | US Navy circumference method |
| 脂肪/肌肉分配 | Forbes 曲线（男 `13.8·ln(FM) + 16.9`，女 `10.4·ln(FM) + 14.2`） |
| 能量密度 | `ED(FM) = 9440.7 − 7624.3 × 10.4/(FM + 10.4)` |
| 代谢适应 | Hall EBMM：`dAT/dt = (0.14·ΔEI − AT)/14` |
| 保肌阈值 | Murphy & Koehler 2022（PMID 34623696）：约 500 kcal/日 |
| 蛋白阈值 | Krieger 阈值 1.05 g/kg |

**为什么不用 7700 kcal/kg**：那个常数只对脂肪量 35kg 左右的人才准。
瘦的人实际是 5500 左右 —— 这就是「越瘦越难减」的量化解释。

## 技术

- **单文件**：`index.html` 装下全部 HTML + CSS + JS，无构建、无 CDN
- **离线**：Service Worker 网络优先（拿得到就用最新，拿不到回缓存）
- **通知**：只支持 https，且页面需在后台；错过的时间点会在回到前台时补发
- **存储**：localStorage，key `ran_fit_v1`
- **背景**：只有一层静态渐变 —— 没有 canvas、没有任何循环动画（滑动性能优先）

## 自动备份

**每天 02:00** 电脑上的定时任务（`FitTrackerDailyBackup`）把数据推到本仓库的 `data.json`。
电脑关机时任务设了「错过后补跑」。

App 内也有即时备份：设置 → 自动备份 → 填 GitHub Token 和仓库名，之后每次打卡自动上传。

## 工具

```
python tools.py backup          同步数据到 GitHub
python tools.py test            跑全部测试
python tools.py check           语法检查 + 测试
python tools.py bump            版本号 +1
python tools.py serve           本地服务器
python tools.py task status     看定时任务
```

**为什么用 Python 而不是 PowerShell**：这个项目全是中文和大量字符串处理。

- PowerShell 的转义规则特殊（反引号是转义符、`$` 会插值），内联代码极易炸
- 而且 `Get-Content` / `Set-Content` **默认按 GBK 读写** —— 这个 README 就被这么弄坏过一次（正确的 UTF-8 被用 GBK 读出来再写回，变成双重编码的乱码）

Python 的三引号和 UTF-8 处理更直接，所以工具全部用 Python。
